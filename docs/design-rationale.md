# 設計根拠 — 市場調査の原則と「湯宿 山霞」の対応

本プロジェクトは、Instagram Reelsで紹介されている商業Webサイト12件の市場調査から抽出した設計原則をもとに設計しています。調査の生データには第三者の投稿情報が含まれるため公開リポジトリには含めず、本書では抽象化した原則と実装の対応だけを記録します。

## ポートフォリオ3部作における位置づけ

調査から得た3つの設計軸を、3作で1つずつ実装しています。

| 作品 | 軸 | 実装手段 |
|---|---|---|
| 菓寮 月白 | 世界観・情緒型 | 伝統色・縦書き・静的CSS/SVG |
| 常盤精工 | 明快さ・信頼型 | 情報階層・スペック表・等幅数字 |
| **湯宿 山霞(本作)** | **没入型** | **素のWebGL2+手書きGLSL** |

## 原則 → 実装の対応

### 1. 「没入型モーションは目的が明確な時のみ価値を持つ」

調査で観察した没入型の成功例は、山岳3D景観+スクロール連動カメラ+霧で「重厚な世界観と技術力そのもの」を信頼要素にしていました。一方で「目的なき派手さは避けるべき」というのが調査の結論です。

本作の題材選定はこの原則から逆算しています。温泉旅館は「霞・湯・灯り」という、**シェーダーで描くこと自体が商品価値の説明になる**題材です。

- ヒーロー: コピー「霞の向こうに、湯の灯り。」をu_scrollでそのまま実装(スクロール=宿にたどり着く体験)
- 水面: 「源泉かけ流しの生きた湯」を波動方程式のシミュレーションで体感させる
- 湯けむり: 湯の温度を視覚で伝える
- 逆に、料理・部屋・案内など「読む」セクションにはシェーダーを置かない

### 2. 重量級表現のモバイル・低速環境リスクに備える

調査は没入型WebGLの弱点として「実装が重くモバイル/低速環境で不利」を挙げていました。本作のガード:

- 3Dライブラリを使わず素のWebGL2(依存ゼロ、JS約236KB・gzip76KBに収まる)
- devicePixelRatio上限(2 / 1.5)・固定解像度シミュレーション(256²)
- 水面シミュレーションを固定120ステップ/秒にし、画面のリフレッシュレートによる速度・負荷の差を抑制
- 画面外/タブ非表示で描画停止、`prefers-reduced-motion`で静止1フレーム
- WebGL2非対応はCSSフォールバック。**情報はすべてDOM側にあり、シェーダーが無くても商業サイトとして完結**

### 3. 高級商材は「世界観・質感」で信頼を作る

旅館は高級商材のため、数値や実績ではなく質感で語ります。架空実績(宿泊者数・口コミ・評価)は一切書かず、六室・源泉・会席という「商品そのものの具体」だけを情報として提示しています。

### 4. ヒーローは「短いコピー+主役ビジュアル+明確な次アクション」

- 情緒コピー(高級商材の定石): 「霞の向こうに、湯の灯り。」
- 業種の即時理解: 直上に「信州・霞谷温泉 — 全六室の湯宿」
- 具体的な動詞句CTA: 「泊まる日を選ぶ」
- 架空である旨の注記をヒーローとフッターに明記

### 5. AI量産物に見える表現の回避

調査が挙げた「文脈のない3D・意味のないグラデ・均質ダークテーマ」を避け、暗さには文脈(夜の谷の宿)を持たせ、生成りの「読む面」と交互に構成しています。ビジュアルはすべて題材から導出した手続き生成(fbm稜線・波動方程式・湯けむり)で、既製の3Dモデルや素材を使っていません。

## 採用しなかった知見とその理由

- **スクロール連動カメラ+被写界深度**: 調査の観察例にあった表現だが、1ページの宿サイトには過剰で、モバイル負荷に見合わないため不採用。スクロール連動は「霞の濃度と灯りの強さ」だけに絞った
- **B2B型の数値による信頼**: 高級商材の軸ではないため不採用(泉質・湯量など商品の事実のみ記載)
- **実在の評価バッジ・口コミ**: 架空の宿では虚偽表示になるため不使用
